# JSON Reading

在 VS Code 中为表格型 JSON / JSONC 数据显示字段名。外层数组的第一个元素为字段名数组，后续每个数组为一条记录，字段按位置对应。

```json
[
  ["ID", "Characters", "Attribute", "Name"],
  [
    1,
    "19010004,19010014",
    [
      "AttackProp:0.10",
      "HpProp:0.10"
    ],
    "示例"
  ]
]
```

光标位于 `1` 所在行时，行尾会出现灰底的 `ID`；位于 `AttackProp:0.10` 或 `HpProp:0.10` 所在行时，会显示 `Attribute`。提示只是编辑器装饰，不会写入文件或影响复制内容。

## 显示模式

默认仅在光标所在行显示；选中多行或使用多个光标时，显示所有被选中的数据行。

- 点击右下角状态栏的 **字段名：选中行 / 全部行** 切换。
- 或执行命令 **JSON Reading: 切换字段名提示（全部行 / 选中行）**。
- 或在设置中搜索 `json-reading.fieldHints.displayMode`，选择 `selected`（仅选中行）或 `all`（全部行）。

```json
"json-reading.fieldHints.displayMode": "all"
```

设置会保存，重新打开文件仍然生效。默认保存到用户设置；若当前工作区或文件夹已有该设置，切换会更新对应作用域。

## 支持范围

- 支持 JSON 和 JSONC，JSONC 允许注释及尾随逗号。
- 字段名必须是首行数组中的字符串；普通 JSON 对象不显示提示。
- 嵌套数组、对象的内部行及括号行显示所属字段名。
- 一行包含多个字段时，按顺序使用 `·` 分隔字段名。
- 记录字段不足时显示已存在字段；超出表头的值不猜测字段名。
- 编辑过程中若 JSON 暂时无效，会清除提示；语法恢复后自动显示。
- 全部行模式随滚动显示当前可见的数据行，解析结果会缓存，编辑更新有 150ms 防抖。

## 开发与验证

```sh
npm install
npm run compile
npm run lint
npm run test:unit
npm test
```

按 F5 启动扩展开发窗口，打开上述格式的 JSON 文件即可体验。`npm test` 运行 VS Code 扩展宿主集成测试，首次运行需要下载匹配版本的 VS Code。

## 策划表字段说明（XLSM）

执行 **JSON Reading: 选择策划表目录**，选择本地策划仓库根目录。也可以在当前工作区设置中添加：

```json
"json-reading.tables.directory": "D:\\策划表\\config"
```

扩展递归查找 `注册表.xlsm`，读取 A 列的页签名和 B 列的导出名，再扫描各 XLSM 的页签来定位源工作簿，无需工作簿名称与 JSON 名称一致。注册表第 1 行作为表头跳过。导出名开头的 `@`（仅前端）、`^`（仅后端）在匹配时移除，两端的说明都可查询。

字段按名称精确匹配，不依赖 JSON 与 Excel 列顺序。默认读取第 **5** 行字段名、第 **3** 行简述和第 **2** 行详细说明。鼠标悬停在行尾字段标签上，可以查看非空说明以及源工作簿文件名、页签名。多个字段共用一行时分别列出说明。

可配置项：

| 设置（前缀为 `json-reading.tables.`） | 默认值 | 用途 |
| --- | --- | --- |
| `directory` | 空 | 根目录；为空时保留原有字段名提示，不读取 XLSM。相对路径基于第一个工作区文件夹。 |
| `registry` | 空 | 注册表相对路径或绝对路径。为空时自动查找；存在多个注册表时需要指定。 |
| `fieldRow` | 5 | 字段名行，从 1 开始。 |
| `descriptionRow` | 3 | 简述行，从 1 开始。 |
| `detailRow` | 2 | 详细说明行，从 1 开始。 |
| `workbookOverrides` | `{}` | 重名页签的选择，如 `{"BingoRewardConfig": "Data/bingo.xlsm"}`。 |

存在同名页签时不会自动猜测，执行 **JSON Reading: 选择当前 JSON 的策划工作簿** 选择并保存。说明读取失败时仍保留行尾字段名，悬浮框显示原因，详细日志在“输出 → JSON Reading”。

根目录内的 XLSM 新增、修改或删除后会自动清空索引并重新查询；连续事件合并等待 500ms。执行 **JSON Reading: 刷新策划表索引** 也可以手动刷新，适用于外部切换分支、拉取更新或文件监听未生效的情况。如果注册表放在根目录外，更新它后请手动刷新。

表格解析只读取 ZIP/XML 内容，不执行宏、不改写单元格。只在受信任的工作区读取策划目录。读取的是磁盘中已经保存的单元格值；不读取 Excel 未保存的修改，也不计算公式（公式单元格使用文件保存的缓存值）。

### 按 JSON 分支更新策划表

悬浮框底部显示 JSON 和策划表的分支，以及内置的刷新图标；分支不一致时显示黄色感叹号。点击刷新图标（或执行 **JSON Reading: 按当前 JSON 分支更新策划表**）会从策划表仓库 `origin` Fetch 同名分支，切换到该分支，然后执行 `pull --ff-only --no-rebase`。本地没有该分支时创建对应的跟踪分支。完成后重新读取字段说明；窗口获得焦点或每 10 秒检查外部分支变化。

需要本机 Git 可执行文件在 PATH 中，且已有远端访问凭据。当前版本按分支名精确对应，使用 `origin`；不支持自定义分支映射。策划表目录可以是仓库的子目录。

策划表仓库有未提交/未跟踪文件、正在合并/变基、远端无同名分支、JSON 为分离 HEAD，或两者属于同一仓库时停止。分叉历史不会自动合并或重置，也不会自动暂存修改。更新前请保存并关闭 Excel 工作簿，避免文件占用或旧工作簿覆盖更新内容。Pull 失败时可能已完成分支切换，此时保留当前状态并重新读取说明。JSON 仓库只读，不受其未提交修改影响。

`tableGit.ts` 负责 Git 检查与同步；`tableGitController.ts` 负责命令、进度和分支状态缓存。网络操作只在点击刷新时执行；不会自动 Pull。

新增模块：`workbookReader.ts` 负责 XLSM 只读解析；`tableIndex.ts` 负责注册关系和页签索引；`tableDescriptions.ts` 负责编辑器配置、异步查询及文件监听；`fieldHover.ts` 负责悬浮内容排版。测试使用生成的最小夹具，不包含真实策划数据。

点击来源文件名可以打开工作簿。在 Windows 桌面版 Microsoft Excel 中，扩展会通过 `scripts/openWorkbook.ps1` 自动激活对应页签，并优先复用当前 Excel 实例中已打开的工作簿。此操作不保存文件；新打开的工作簿禁用 VBA 宏且不更新外部链接。隐藏页签不会自动取消隐藏。其他系统只打开文件，需要手动选择页签。

客户端 JSON 文件匹配前会直接去掉末尾一个 `Data` 后缀（不区分大小写）。例如 `BingoRewardConfigData.json` 查询注册名 `BingoRewardConfig`，不再优先匹配完整文件名。文件名中间的 `Data` 和注册表中的名称保持不变；没有此后缀的文件按原名查询。重名工作簿选择仍按实际 JSON 文件名保存。

### 中文翻译与关联候选

首列 ID 固定跳过，不参与关联查询。其他字段的 `i18n_…` 从 JSON 同目录的 `i18zhConfigData.json` 按 `KeyID` 查询 `Desc`；可以通过 `json-reading.relations.i18nFile` 指定其他位置。语言表采用首行字段名的二维数组格式，读取磁盘上已保存的内容。

打开其他字段时，扩展只读取共享匹配表中已经配置且未排除的目标，不自动按数值全表扫描。缺少规则的字段保留为未配置，不把“未分析”当成“没有关联”。初始匹配表可以通过离线分析项目代码生成，扩展运行时无需调用 AI。i18n 仍直接查询中文表。

规则支持固定目标、按同一记录的其他字段分流、组合字符串提取，以及目标表的非 ID 键。例如仅在 `ItemType` 为 `2` 时，提取 `Rewards` 中 `1001:20,1002:30` 的两个 ID：

```json
{
  "target": { "file": "Data/mine.xlsm", "sheet": "矿石", "names": ["oreconfig"] },
  "decision": "accepted",
  "when": { "field": "ItemType", "values": [2] },
  "extract": { "listSeparator": ",", "separator": ":", "index": 0 }
}
```

`when`、`extract` 都可省略；`index` 从 0 开始，嵌套数组中的每个字符串分别提取，`listSeparator` 可省略。原生数组 `[1001,20]` 可用 `extract: { "arrayIndex": 0 }` 只取 ID；也能先选数组项再按分隔符提取。目标键默认 `ID`（不区分大小写），需要关联分组等字段时可在 `target` 中指定 `keyField`。没有提取规则的 `1001,20` 按整体值查询，不自行猜测 ID 和数量。规则只保存匹配所需信息，不保存代码依据或 AI/人工来源标记。

Hover 在每个字段的描述后显示“无匹配”或“已匹配：表名 / 页签名”，同一目标只显示一次，不再列出原始值和逐条匹配记录。点击目标链接会打开对应 XLSM 并定位页签，与来源链接行为一致。待确认候选显示绿勾确认、红叉排除；已确认的关联只显示红叉。同一目标包含待确认规则时仍保留绿勾。“已匹配”表示当前值在目标表中有记录，不等于已经人工确认。

每个字段可以配置多个目标，同一目标的不同条件规则仍分别保存。合并显示后的确认/排除按钮只操作该目标在当前悬浮内容中命中的规则，不影响其他目标或未生效的条件。i18n 中文翻译继续显示。读取中、读取失败会显示相应状态，不会误报为“无匹配”。

匹配规则统一保存在 **项目根目录的 `extensions/json_reading/relations.json`**，一个项目只有一个共享匹配文件。例如打开 `D:\cn` 项目时，保存到 `D:\cn\extensions\json_reading\relations.json`。生成初始表或首次手动保存规则时创建；可以提交到 Git 供团队共享。内部按 **源 JSON 的项目相对路径 → 字段列号与字段名 → 目标与条件规则** 分组，工作簿同样使用相对策划目录的路径，不包含成员个人的磁盘路径。

重启后保留确认、排除、待确认候选以及“已扫描但无结果”；后续只查询已知且未排除的目标，不自动全扫描。读取失败不会被保存成空结果。多根工作区分别写入源 JSON 所属的文件夹；JSON 不在工作区内时尝试使用其 Git 根目录，找不到时提示打开对应项目。旧版 workspaceState 规则读取后在下次手动保存时迁移，新文件已有规则则优先使用新文件；旧版无条件规则继续兼容。

保存前重新读取并合并规则，清空操作只删除该源 JSON 的条目。共享文件外部修改或拉取后会重新读取；遇到格式错误、Git 冲突标记或编辑器中未保存的匹配表修改时停止写入。多个本地窗口通过短期锁文件协调写入，正常完成后只保留 `relations.json`；团队 Git 合并冲突仍需人工解决。

匹配表顶层是 `{ "version": 1, "files": { ... } }` 对象，并且扩展明确排除该文件，所以打开它不会触发字段装饰或关联扫描。普通对象 JSON、对象数组、普通数字数组不会被识别为表格；只有首项是非空字符串字段名数组、后续包含数据数组的 JSON 才显示字段提示。JSONC 可包含注释和尾随逗号，语法不完整时暂不提示。

- **手动全搜索**（悬浮按钮暂时隐藏，命令面板入口保留）：只汇总当前字段在所有记录中的值，扫描各 XLSM 页签的 ID 列；按列号与字段名定位，不搜索或修改其他字段。保留已有规则并补充尚未记录的目标，已有条件规则的目标不会再补成无条件关联。仅值相等的结果是待确认候选，不代表已验证业务含义。
- **清空匹配表**（垃圾桶图标）：只删除当前 JSON 的全部匹配记录，不自动启动全扫描，不影响其他 JSON。需要重新查找时点击手动全搜索。

两个操作也可以通过命令面板执行：**JSON Reading: 手动全搜索当前字段的关联**、**JSON Reading: 清空当前 JSON 的关联匹配表**。命令面板搜索按光标所在字段执行，同一位置有多个字段时选择其中一个，首列 ID 不参与。搜索、清空、确认和排除在底部状态栏显示进度，完成或失败后弹出通知。策划表更新或 Git 切换后会刷新数据索引，但保留匹配规则；新增关联可以编辑共享文件或使用手动全搜索补充。当前版本不递归展开关联。

模块：`relations.ts` 负责值提取、全表索引和翻译；`relationStore.ts` 保存每个 JSON 的规则；`relationController.ts` 负责异步查询与按钮；`relationHover.ts` 负责展示候选。

### 离线生成初始匹配表

开发脚本先读取 JSON / 注册表清单，再分析客户端 TypeScript 中配置字段如何传入查询函数。它能识别直接字段传递、部分简单包装方法、明确的行条件和 ID 提取，不保证识别跨多层动态分派或仅在服务端使用的关联。运行时不调用 AI。脚本生成的建议需结合业务代码检查后再合并，不能以数值命中率代替业务关系判断。

以下命令在本扩展源码目录运行，输出默认放在 Git 忽略的 `.vscode-test` 中：

```powershell
npm run compile
node scripts/inventory-client-config.cjs D:\cn D:\策划表\config .vscode-test/inventory.json
node scripts/analyze-client-relations.cjs D:\cn .vscode-test/inventory.json .vscode-test/proposals.json
node scripts/build-client-relation-map.cjs D:\cn .vscode-test/inventory.json .vscode-test/relations.generated.json .vscode-test/proposals.json
```

生成器为 `assets/resources/ClientConfig` 的每个 JSON 建立条目，首列不生成字段规则；非表格文件条目为空。没有确定目标的字段保存为空，不触发自动扫描。它通过注册名定位唯一工作簿及页签，目标不唯一、缺少查询字段等情况记录在输出旁的 `.summary.json` 中并跳过，不猜测工作簿。

可在命令末尾追加多份经过检查的建议文件。每条建议包含 `source`（来源配置名）、`field`、`target`（目标注册名），以及可选的 `when`、`extract`、`keyField`。生成器会读取工程现有匹配表，保留已确认和已排除的规则，替换旧的待确认候选；完整结果写入指定输出，不直接覆盖工程。检查结果后，将其替换为项目中的 `extensions/json_reading/relations.json`。匹配表只保留运行时需要的规则，分析记录不会写入共享文件。
